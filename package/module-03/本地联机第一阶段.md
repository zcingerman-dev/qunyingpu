# 本地联机第一阶段

入口：基础实战页面的“单挑”下方 → 本地联机。第一阶段支持同一台电脑的两个浏览器客户端，标准包、单将、点将单挑、标准＋军争牌堆。此范围用于验证联机基础链路，未扩展到其他模式或第二阶段。

## 已审计的引擎入口

| 项目 | 当前来源 | 第一阶段处理 |
| --- | --- | --- |
| 正式状态 | `engine/noname/game/index.js` 的 `game.players/dead`、玩家卡牌区域与 storage；`_status` 当前事件与暂停；`ui.cardPile/discardPile` | 只在Host引擎框架内执行；不是将DOM当成客户端正式状态 |
| 真人输入 | `GameEvent.isMine()`；原生 `chooseToUse/chooseToRespond/chooseCard/chooseTarget/chooseButton/chooseBool/chooseControl`；`ui.click` 与 `game.check()` | 模式专用输入适配，导出当前合法引用；Client提交ACTION，Host重验后调用原生操作入口 |
| 临时选择状态 | `ui.selected.cards/targets/buttons`、当前选择事件的 backup、确认与结束按钮 | 同样属于Host；选择一个牌、目标或技能也须经过ACTION |
| AI | 非真人选择进入原生事件中的AI分支；批量测试另有 `local-controller.js/model-controller.js` | 联机两席均为真人，不启用批量优化控制器；单机AI路径继续保留 |
| 随机数 | 原生 `get.rand`、数组随机选取和洗牌使用 `Math.random`；启动入口预先设置随机函数 | Host在导入引擎之前安装带计数的种子随机源；Client仅生成操作ID，不决定游戏随机结果 |
| 执行结果 | 原生 `game.addVideo()` 和事件完成结果 | 发出ENGINE/ENGINE_RESOLVED/MATCH_OVER事件并发布快照，区别于单纯收到操作的ACK |

没有修改武将技能定义、数值或平衡，也没有逐技能改造。原单机开局的随机路径保持独立；联机适配只在具有 `launch.network` 的Host启动中安装。

## 架构与维护路径

```text
Host真人页面 / Client真人页面
  ACTION（当前提示ID、提示版本、候选引用）
    → HttpTransport → 本机Python转发器
    → Host验证座位、版本、候选和原生规则
    → 唯一原生Game Engine
    → EVENT + SNAPSHOT
    → 两端ClientReplica只读副本与操作面板
```

- `network-store.py`：内存会话、成员凭据、不可伪造的座位绑定、ACTION去重和队列、Host专用发布权限、一次性引擎启动租约。不执行游戏规则。
- `network-transport.js`：统一 `connect/send/onMessage/onError/close` 接口；HTTP轮询实现；供测试使用的Memory Transport；只读副本 `ClientReplica`。
- `network-host.js`：原生输入适配与验证、稳定的 `playSeat`、公开状态、每席私有视图、引擎事件和结束状态。使用 `swapControl`，避免 `swapPlayer` 旋转座位。
- `network-random.js`：Host的种子随机源。当前引擎的表现随机与游戏随机共同消耗这一Host随机流，不承诺随机调用次数跨引擎版本不变。
- `network-ui.js/network.html/network.css`：建立Host、加入Client、开局、显示状态及提交选择。Client不导入原生引擎，不通过乐观更新修改正式状态。
- `arena-boot.js/bridge.js`：仅增加可选联机分支；原本单机入口与保存流程继续可用。

## 相对接口

以下地址相对于本地联机页面目录，迁移电脑无需修改盘符、用户路径或端口。

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `POST ./api/network/create` | 建立Host会话及选将 | 本机页面 |
| `POST ./api/network/join` | Client加入会话码 | 本机页面 |
| `POST ./api/network/{room}/start` | 新建联机对局 | Host成员 |
| `GET ./api/network/{room}/launch` | 获取一次性引擎启动数据 | Host引擎凭据 |
| `POST ./api/network/{room}/action` | 提交ACTION | 已绑定成员，服务端绑定座位 |
| `GET ./api/network/{room}/inbox` | 读取待验证ACTION | Host引擎 |
| `POST ./api/network/{room}/publish` | 发布EVENT/SNAPSHOT及确认序号 | Host引擎 |
| `GET ./api/network/{room}/poll?after={seq}` | 读取快照和新增事件 | 已绑定成员 |
| `POST ./api/network/{room}/close` | 结束会话 | Host成员 |

所有写入继续使用当前本机页面校验；会话访问另带 `X-Room-Token`。客户端不能提交任意技能代码、JS、GameState、体力修改或伪造座位。Host控制器会拒绝错误座位、旧提示、假引用及不满足数量/目标条件的操作；引用来自当前原生合法候选，而不是按客户端传入的名字自行查找任意对象。

## 验收方法

1. 同一电脑打开两个“本地联机”页面。第一页选标准武将，建立Host；第二页输入会话码，以Client加入。只有Host可在双方到齐后开局。
2. 在出现操作提示的一端选择牌、目标并确认；另一端响应。选择关羽可检查“武圣 → 红牌 → 目标 → 确定”。如果当前没有红牌，正常结束回合后再试。
3. 展开两端“联机事件与状态核对”，稳定等待操作时公开状态校验值应一致；EVENT中可看到ACTION接受/拒绝以及原生结算事件。
4. Client刷新后可用本标签页保存的成员凭据恢复最新视图；不会重开一份引擎。Host须保持页面打开。
5. 回到原基础实战，按原方式开启单机/AI对局。

## 已知限制与停止边界

- 仅环回地址和同机两席；未实现WebRTC、互联网房间、跨电脑连接或房主迁移。
- 会话在内存中，服务重启或Host页面重载后需新建；旧Host引擎租约不重新发放。对局原生日志仍走既有记录接口，但不等同于联机会话恢复。
- 客户端断开时保留座位并等待，不自动AI接管。Host临时通信故障会显示异常；已提交但未处理的操作保留在队列。
- 普通牌、目标、按钮、确认、控制选项及标准ViewAs技能已有适配；拖动排序等专用界面尚未完整接入，显示等待或未接通提示，不擅自代选。
- 普通视图按座位提供自己手牌与自己的提示，但尚不是最终隐藏信息安全方案；本机Host拥有全部正式状态，同源访问与恶意调试不是本阶段解决目标。
- HTTP轮询约150毫秒一次，使用完整快照恢复视图；公开状态校验值用于发现同步差异，不是安全签名。ACTION_ID在会话内去重，队列和事件缓存有大小限制。
- 本阶段完成后停止，不自动进入第二阶段，不重新核查冻结PASS技能。

## 自动测试

工作区的 `work/test_network.py` 验证后端权限、去重、队列、状态副本与模式设置；`work/test_network.mjs` 验证Transport、ClientReplica和Host随机源；`work/network_native_server.py` 提供与正式数据隔离的原生HTTP多客户端场景。结果汇总写入 `work/network-phase1-verification.json`。测试服务器不属于产品运行依赖。
